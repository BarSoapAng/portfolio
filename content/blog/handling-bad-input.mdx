When you let people be responsible for their own inputs, you inevitably get some... *interesting* inputs.

NSFW content and "bad" words are probably the most common examples, so let's go over how this site handles them!

## The problem

Text inputs risk containing profanity, and drawings risk containing, well, absolutely anything. Giving users so much freedom also requires a lot of behind-the-scenes logic to make sure that freedom is used responsibly.

And obviously, for a site built by a SWE for an audience of other SWEs, we also have to handle malicious inputs :3

## Text

For name inputs, I simply check the name against the `bad-words` package, a [JavaScript package](https://www.npmjs.com/package/bad-words) that filters out bad words for you!

## Drawing

**Empty case:** Disable submission when the canvas is empty.

**NSFW case:** Before uploading, the browser runs `NSFWJS` to classify the drawing. This [open-source model](https://github.com/infinitered/nsfwjs) predicts the likelihood of explicit content across five different categories. The content warning triggers if any one of the categories exceeds `30%`.

- This is a client-side check!
- The trade-off is a slightly worse UX due to slower upload times.

The UX problem is actually a pretty difficult one to solve. Loading TensorFlow and the model on submission takes significant memory, often causing lag or freezing. A few things improve this:

- Cap the drawing snapshot history (for undo/redo) at 15.
- Load the model in the background after the first canvas interaction.
- Load TensorFlow and NSFWJS concurrently.

**Malicious case:** Luckily, displaying images (as long as their content isn't inappropriate) is quite safe! Both the frontend and backend accept only image file types :)
